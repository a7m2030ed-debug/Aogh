# نسيج — متجر أقمشة رجالية

متجر إلكتروني كامل للأقمشة الرجالية: **صيفية** مصنَّفة بالوقفة، **شتوية**، و**طاقات** للجملة.

يعمل في وضعين، ويختار بينهما تلقائيًا بلا إعداد:

| | وضع العرض | وضع الخادم |
|---|---|---|
| **متى** | استضافة ثابتة مثل GitHub Pages | حين يعمل `fabric/server` |
| **البيانات** | في متصفح كل زائر وحده | قاعدة واحدة مشتركة |
| **الطلبات** | لا تصل أحدًا | تصل لوحتك |
| **الدفع** | محاكاة | بوابة حقيقية |
| **يصلح لـ** | المعاينة والعرض | البيع |

نفس الملفات في الوضعين: المتجر يجرّب `/api/catalog`، فإن ردّ عمل بوضع الخادم، وإلا
رجع لوضع العرض وأظهر شريطًا يخبر الزائر أن طلبه لن يصل أحدًا.

**للتشغيل الحقيقي:** [`fabric/server/README.md`](server/README.md).

```
cd fabric/server && node server.js      # بلا npm install
```

| الصفحة | ما هي |
|---|---|
| `fabric/index.html` | واجهة العميل: تصفّح، سلة، دفع، تتبّع |
| `fabric/admin.html` | المنتجات، الطلبات، المخزون، الإعدادات |

## ما الذي بُني

### ١ · الهيكل والأقسام

* **الصفحة الرئيسية** — بانر متحرك بثلاث شرائح، بطاقات الأقسام الثلاثة، رفّ «الأكثر مبيعًا»، دليل الوقفة المبسّط، ثم «مختارات الموسم».
* **قائمة المنتجات** — لكل قسم صفحته مع فرز (رواجًا · الأحدث · السعر صعودًا/نزولًا). القسم الصيفي **وحده** يحمل فلاتر الوقفة الأربعة: الطايح · ربع وقفة · نصف واقف · واقف، والفلتر يُحفظ في الرابط (`#/c/summer?w=nisf`) فيُشارَك ويُحفَظ في المفضّلة.
* **صفحة المنتج** — معرض متعدد (صورة عامة، صورة مقرَّبة للنسيج، صورة بديلة، ومعاينة حركة القماش)، جدول مواصفات (الصناعة · التركيب · الوزن · العرض · الوقفة · الموسم · العناية)، اختيار الكمية بالمتر أو بالطاقة، وحاسبة «كم مترًا أحتاج؟» حسب الطول.
* **السلة والدفع** — درج سلة جانبي، ثم دفع من ثلاث خطوات: البيانات ← الشحن ← الدفع، مع ملخص طلب ثابت بجانب النموذج.
* **تتبّع الطلب** وصفحات الشحن والاسترجاع والشروط والخصوصية.

### ٢ · الوقفة

الوقفة هي محور تصنيف القسم الصيفي، وهي مطبَّقة في أربعة مواضع: فلاتر القسم، شارة على بطاقة المنتج، صف في جدول المواصفات، وصفحة دليل مستقلة برسم توضيحي لسقوط القماش يتغيّر بتغيّر القوام. وفي لوحة التحكم يمنع النظام حفظ أي قماش صيفي بلا وقفة.

### ٣ · المخزون الذكي

نوعا بيع مستقلان لكل قماش، ولكلٍّ سعره ومخزونه وحدّ تنبيهه:

| | الوحدة | الخصم عند الطلب | حد التنبيه |
|---|---|---|---|
| **بيع بالمتر** | متر (بخطوة نصف متر) | بالأمتار من رصيد الأمتار | افتراضيًا 30 م |
| **بيع بالطاقة** | طاقة (45 – 50 م) | بعدد الطاقات | افتراضيًا طاقتان |

* القماش الواحد قد يُباع بالطريقتين معًا، فتظهر له في صفحة المنتج تبويبتان.
* السلة ترفض أي كمية تتجاوز المتاح وتُظهر الرصيد الفعلي.
* في وضع الخادم تُحجز الكمية لحظة إنشاء الطلب فلا يبيع طلبان متزامنان نفس
  القطعة، ثم يتحول الحجز إلى خصم عند تأكيد الدفع. والحجز المهجور يُفرَج عنه.
* **تنبيه النفاد** يظهر في لوحة المعلومات وفي صفحة المخزون بمجرد نزول أي صنف إلى حدّه أو دونه، مع زر «تزويد» يفتح المنتج مباشرة.

### ٤ · لوحة التحكم

* **لوحة المعلومات** — مبيعات آخر 7 أيام مقارنةً بالسبعة التي قبلها، الطلبات المفتوحة، عدد الأقمشة، الأمتار المباعة، تنبيه المخزون، أحدث الطلبات، وترتيب الأكثر مبيعًا.
* **المنتجات** — إضافة وتعديل وحذف، رفع الصور والفيديو، تحديد القسم والوقفة، وضبط البيع بالمتر والطاقة. الرمز (SKU) لا يتكرر، ولا يُحفظ قماش بلا وسيلة بيع واحدة على الأقل.
* **الطلبات** — تصفية بالحالة، فتح الطلب، تغيير الحالة (جديد · قيد التنفيذ · تم الشحن · تم التسليم · ملغي) مع سجل زمني، إصدار بوليصة شحن وطباعتها، عرض الفاتورة الضريبية، وإلغاء الطلب مع إعادة كميته للمخزون.
* **المخزون والأسعار** — جدول تعديل مباشر: السعر والمخزون وحدّ التنبيه لكل وسيلة بيع، يُحفظ فور الخروج من الخانة.
* **الإعدادات** — بيانات المتجر، الضريبة، حد الشحن المجاني، أمتار الثوب، شركات الشحن، وسائل الدفع، وتصدير/استيراد/تصفير البيانات.

### ٥ · تجربة الاستخدام

* **الجوال أولًا** — كل التصميم مبني من عرض 320 بكسل صعودًا، وزر «أضف للسلة» مثبّت أسفل الشاشة مع الإجمالي الحيّ.
* **بلا موارد خارجية** — الصور مولَّدة داخل الصفحة كـSVG، والخطوط من الجهاز. لا يُحمَّل شيء من أي نطاق آخر، فالصفحة تفتح فورًا ولا تسرّب زيارات زبائنك لأحد.
* الأرقام كلها بالخانات اللاتينية (`175 ر.س`) اتساقًا مع ما يعتاده السوق السعودي، والتواريخ ميلادية.

## الملفات

```
fabric/
├── index.html        واجهة المتجر
├── admin.html        لوحة التحكم
├── assets/
│   ├── styles.css    نظام التصميم (الصفحتان تشتركان فيه)
│   ├── api.js        عميل الواجهة البرمجية واكتشاف الوضع
│   ├── data.js       نموذج البيانات والسلة ← ابدأ من هنا
│   ├── shop.js       شاشات المتجر والتوجيه
│   └── admin.js      شاشات لوحة التحكم
└── server/           الخادم — اقرأ server/README.md
```

`data.js` هو الطبقة الوحيدة التي تعرف من أين تأتي البيانات. كل ما في `shop.js`
و`admin.js` يمرّ عبر `Shop.DB` و`Shop.Cart`، فالشاشات لا تعرف أي وضع يعمل.

### أين تُحفظ البيانات

**في وضع الخادم:** في `fabric/server/data` على خادمك. انسخ المجلد للنسخ الاحتياطي.

**في وضع العرض:** في متصفح كل جهاز وحده تحت هذه المفاتيح:

| المفتاح | المحتوى |
|---|---|
| `naseej.products.v1` | الكتالوج |
| `naseej.orders.v1` | الطلبات |
| `naseej.settings.v1` | الإعدادات |
| `naseej.cart.v1` | سلة الزائر |
| `naseej.seq.v1` | عدّاد أرقام الطلبات |

أي أن ما تراه في جوالك غير ما تراه في حاسبك، وتفريغ بيانات المتصفح يمحوها. هذا
وضع معاينة لا بيع، وتشغيل الخادم هو ما يعالجه.

## ما يلزم قبل التشغيل الحقيقي

البرمجة اكتملت: الواجهة والخادم وقواعد المال والمخزون والفاتورة الضريبية.
ما تبقّى ليس كودًا، بل حسابات وأوراق لا يمكن لأحد غيرك استخراجها:

### ما عليك أنت

| البند | يلزم لـ |
|---|---|
| سجل تجاري أو وثيقة عمل حر | فتح حساب لدى بوابة الدفع |
| التسجيل في منصة «معروف» | تطلبه البوابات عادةً لمتاجر التجزئة |
| التسجيل الضريبي | تحصيل الـ15٪ قانونيًا وإصدار فاتورة معتمدة |
| حساب بنكي باسم المنشأة | تحويل المبيعات |
| حساب لدى PayTabs أو MyFatoorah أو Tap | الدفع الإلكتروني |
| عقد مع أرامكس أو سمسا | البوليصات وأسعار الشحن الآلية |
| خادم يشغّل Node (VPS بمعالج وذاكرة 1غ يكفي) | تشغيل الخادم |
| نطاق | عنوان المتجر |
| صور المنتجات الحقيقية | لا يُباع قماش بصور مولَّدة |

تحقّق من المتطلبات النظامية السارية بنفسك، فهي تتغيّر.

النشر نفسه مُجهَّز: على خادم أوبونتو جديد أمر واحد يضبط كل شيء، والتفاصيل
والخيارات في [`server/deploy/README.md`](server/deploy/README.md).

### ما يبقى من البرمجة بعد وصول حساباتك

* وضع مفاتيح البوابة في `.env` وتجربتها على بيئة الاختبار.
* استكمال محوّل شركة الشحن بدليل الربط الذي يصلك مع العقد. حتى ذلك يعمل
  الإصدار اليدوي وتُدخل رقم البوليصة الرسمي من اللوحة.
* استكمال الفاتورة الضريبية: شهادة التوقيع والختم التشفيري وإرسالها للهيئة.
  التفاصيل في [`server/README.md`](server/README.md#الفاتورة-الضريبية).

### قبل النشر

* **إن لم تكن مسجَّلًا ضريبيًا، أطفئ الضريبة من الإعدادات.** المتجر يحتسب 15٪
  افتراضيًا، وتحصيلها بلا تسجيل مخالفة.
* غيّر كلمة مرور المدير من اللوحة. تُطبع مرة واحدة عند أول تشغيل.
* فرّغ الكتالوج التجريبي وأدخل أقمشتك.
* راجع نصوص الشحن والاسترجاع والشروط والخصوصية: مكتوبة كمسوّدة معقولة، وتحتاج
  مطابقتها لسياساتك الفعلية.

## التطوير

لا بناء ولا اعتماديات. حرّر الملف وحدّث الصفحة. للتشغيل محليًا:

```
python3 -m http.server 8000
# ثم افتح http://localhost:8000/fabric/
```

يجب تشغيلها عبر خادم لا بفتح الملف مباشرة (`file://`)، لأن المتصفح يمنع `localStorage`
على ذلك البروتوكول.

لتغيير الكتالوج المبدئي عدّل `seedProducts()` في `assets/data.js`، ثم صفّر البيانات من
الإعدادات ← البيانات ليُعاد توليده. ونفس الكتالوج يستعمله `server/seed-demo.js`،
فلا يفترق المصدران.

اختبارات الخادم:

```
cd fabric/server && node test/run.js
```

الصفحة مستقلة تمامًا عن بقية المستودع: لا تشترك مع `index.html` في الجذر ولا مع
`build_pages.py` في شيء.
