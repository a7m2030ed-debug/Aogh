# النشر

كل ما يلزم لرفع المتجر على الإنترنت جاهز في هذا المجلد. ما لا يمكن لأحد غيرك
فعله: **شراء الاستضافة والنطاق**، لأنهما يحتاجان بطاقتك وهويتك.

الخلاصة: تشتري خادمًا ونطاقًا، ثم تشغّل أمرًا واحدًا.

---

## ١ · النطاق

| النوع | متى | الملاحظات |
|---|---|---|
| `.com` | الأسرع | يُسجَّل فورًا بلا أوراق، وهو الأوسع قبولًا |
| `.sa` أو `.com.sa` | هوية سعودية أوضح | يُسجَّل عبر مُسجِّل معتمد لدى SaudiNIC، ويطلب عادةً سجلك التجاري فتأخذ مراجعته وقتًا |

لا يمنع شيء من البدء بـ`.com` وإضافة `.com.sa` لاحقًا يشير إلى الموقع نفسه.

**السعر:** نطاق `.com` عادةً في نطاق عشرات الريالات سنويًا، و`.sa` أعلى قليلًا.
تحقّق من السعر الحالي عند المُسجِّل، فالأسعار تتغيّر.

**ما ستفعله بعد الشراء:** سجل `A` واحد يشير إلى عنوان خادمك (يعطيك إياه مزوّد
الاستضافة). سطر واحد في لوحة النطاق. هذا كل شيء.

---

## ٢ · الاستضافة

المتجر يحتاج استضافة **تشغّل Node**. الاستضافة المشتركة العادية وGitHub Pages
لا تصلح لأنها تخدم ملفات ثابتة فقط.

### الخيار الأول: خادم افتراضي (VPS) — الأوصى

أرخص وأكثرها تحكّمًا، والسكربت يجهّزه كاملًا.

**المواصفات الكافية:** معالج واحد، ذاكرة 1 غيغابايت، قرص 20 غيغابايت. متجر
أقمشة لا يحتاج أكثر. التكلفة عادةً في حدود عشرات الريالات شهريًا.

**مزوّدون:** Hetzner وDigitalOcean وLinode وVultr عالميًا، ومزوّدون محليون إن
أردت البيانات داخل المملكة. اختر **Ubuntu 22.04 أو 24.04**.

اختيار الموقع الجغرافي يؤثر على سرعة الموقع لزبائنك: الأقرب للسعودية أفضل
(بعض المزوّدين لديهم مراكز في البحرين أو الإمارات أو فرانكفورت).

**الخطوات:**

```bash
# 1. من جهازك: انسخ المتجر إلى الخادم
scp -r fabric root@عنوان-خادمك:/tmp/

# 2. ادخل الخادم
ssh root@عنوان-خادمك

# 3. أمر واحد يجهّز كل شيء
cd /tmp/fabric/server/deploy
bash setup.sh نطاقك.com بريدك@example.com
```

السكربت يثبّت Node، وينشئ مستخدم نظام بصلاحيات ضيقة، ويشغّل الخدمة بحيث تعود
بعد أي إعادة تشغيل، ويضبط Nginx، ويصدر شهادة https مجانية تتجدّد تلقائيًا،
ويغلق كل المنافذ إلا الضرورية، ويجدول نسخة احتياطية يومية. آمن للتكرار: تشغيله
ثانيةً يحدّث ولا يكسر شيئًا، ولا يمسّ بياناتك ولا ملف `.env`.

### الخيار الثاني: منصّة بالنقر

أسهل، وأغلى قليلًا، وتحتاج انتباهًا لنقطة واحدة.

| المنصّة | الملف الجاهز |
|---|---|
| Render | `render.yaml` |
| Fly.io | `fly.toml` |
| أي منصّة تقبل الحاويات | `Dockerfile` |

> **مهم:** اربط **قرصًا دائمًا** واضبط `DATA_DIR` عليه. المنصّات تمسح نظام
> الملفات مع كل نشر جديد، فبدون القرص الدائم **تضيع كل الطلبات والمنتجات** عند
> أول تحديث. الملفات هنا تضبط هذا لك، فلا تحذف قسم `disk` أو `mounts`.

### الخيار الثالث: حاوية على خادمك

```bash
cd fabric
docker compose -f server/deploy/docker-compose.yml up -d
```

البيانات في حجم `naseej-data` تبقى بعد كل تحديث.

## ٣ · قبل أول بيع

```bash
node deploy/preflight.js https://نطاقك
```

يفحص خادمك الحقيقي ويقول هل يصلح لاستقبال أول ريال: الشهادة، ومفاتيح البوابة،
والرقم الضريبي، وكلمة مرور المدير، وأن ملف الأسرار غير قابل للتنزيل، وأن
مسارات اللوحة محمية. يفرّق بين **موانع** يجب حلّها و**تنبيهات** للمراجعة،
ويخرج برمز خطأ إن وُجد مانع.

لا تطلق قبل أن يقول «جاهز للإطلاق».

## ٤ · بعد النشر

### كلمة مرور المدير

تُطبع مرة واحدة عند أول تشغيل:

```bash
journalctl -u naseej | grep -A3 'كلمة المرور'
```

غيّرها من اللوحة فورًا.

### مفاتيح بوابة الدفع

```bash
nano /srv/naseej/server/.env     # ضع PAYMENT_PROVIDER ومفاتيحك
systemctl restart naseej
```

وفي لوحة البوابة اضبط عنوان الإشعار على:

```
https://نطاقك/api/payments/webhook/<اسم-البوابة>
```

### أوامر يومية

| الأمر | ماذا يفعل |
|---|---|
| `systemctl status naseej` | حالة الخدمة |
| `systemctl restart naseej` | إعادة التشغيل بعد تعديل `.env` |
| `journalctl -u naseej -f` | متابعة السجل لحظة بلحظة |
| `naseej-backup` | نسخة احتياطية الآن |

### تحديث المتجر لاحقًا

انسخ الملفات الجديدة ثم شغّل `setup.sh` مرة أخرى بنفس النطاق. بياناتك و`.env`
لا تُمَس.

### النسخ الاحتياطي

نسخة يومية تلقائية في `/srv/naseej/backups`، ويُحتفظ بآخر ثلاثين. **انقل نسخة
خارج الخادم دوريًا** — نسخة على نفس الجهاز لا تنفع إن فُقد الجهاز.

---

## ما الذي لا يفعله هذا المجلد

* **لا يشتري لك نطاقًا ولا خادمًا.** كلاهما يحتاج بطاقتك وهويتك.
* **لا يسجّلك لدى بوابة دفع.** يحتاج سجلك التجاري وحسابك البنكي.
* **لا يضع مفاتيحك.** تضعها أنت في `.env`، ولا تُرفع إلى المستودع أبدًا
  (`.gitignore` يمنعها).

## أخطاء شائعة

**«فشل إصدار الشهادة»** — النطاق لا يشير إلى الخادم بعد. تحقّق بـ
`getent hosts نطاقك`، وانتظر انتشار سجل `A` (قد يأخذ دقائق إلى ساعات) ثم:
`certbot --nginx -d نطاقك`.

**«الخدمة لا تعمل»** — اقرأ السبب: `journalctl -u naseej -n 50`.

**«البوابة لا ترسل الإشعار»** — تأكد أن `PUBLIC_URL` هو نطاقك بـhttps وأن عنوان
الإشعار في لوحة البوابة يطابقه. البوابة لا تصل إلى `localhost`.

**«ضاعت الطلبات بعد التحديث»** — على منصّة بالنقر بلا قرص دائم. اربط القرص
واضبط `DATA_DIR` عليه.
